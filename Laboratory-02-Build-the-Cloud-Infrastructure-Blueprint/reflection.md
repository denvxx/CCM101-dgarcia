# Reflection

The most important cloud infrastructure component, in my view, is networking. Without a working network, a user cannot reach compute resources or access stored data, no matter how powerful the servers are. Networking connects every other part of the system together, which makes it the foundation that allows cloud services to function.

Linux supports cloud computing by acting as the operating system for most cloud servers. It is stable, secure, and can run efficiently on many different types of hardware. Cloud providers use Linux because it allows them to manage large numbers of servers with tools that are flexible and well-documented.

Technical documentation is important before deploying infrastructure because it helps engineers understand what has been built and why certain decisions were made. Without clear documentation, mistakes are harder to find, and it becomes difficult for other team members to maintain or improve the system later. Good documentation also protects the company from confusion if the original engineer is no longer available.

During this laboratory activity, I learned how to check detailed system information on a Linux server, including CPU, memory, disk space, and network details. I also learned how to compare cloud providers by researching their official documentation and organizing the information into a clear table. In addition, I practiced designing a simple cloud architecture diagram to visually explain how different components connect.

My GitHub portfolio has improved because it now contains a second laboratory activity with more advanced documentation. It shows that I can investigate a server, compare cloud providers, and create diagrams, not just basic Linux commands. This makes my portfolio look more complete and closer to the kind of work a real cloud engineer would produce for a client.
